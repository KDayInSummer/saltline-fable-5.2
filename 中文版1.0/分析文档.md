## 0. 摘要

### 0.1 一句话架构

一个 HTML 文件里装着：CSS 设计系统 + 骨架 DOM + 打包进来的 three.js r180 + 约 690 KB 游戏代码（含 27 套 GLSL 程序化材质、1 套程序化天空、1 套湿地面/平面反射、全部音效与音乐的实时合成、全部模型与贴图的代码生成），通过一条**分阶段异步启动流水线**装配成第一人称射击游戏。

### 0.2 关键指标（实测）

|---|---|---|
| 文件总大小 | 1,429,762 B | 约 1.36 MB |

> **修正一个常见误解**：常有人说“1.4 MB 里只有 300 多 KB 的 three.js”。实测 three.js 占约 **706 KB（49%）**，游戏代码约 **692 KB（48%）**。也就是说这不是“极限压缩”的产物，而是一个**正常体积的 three.js 项目 + 正常体积的游戏逻辑**，被打包成一个文件。真正的成就不在体积，在“零美术资源”。

### 0.3 三条设计主线

1. **资源全程序化**：材质、天空、地面、模型、标牌、音效、音乐全部由代码生成，仓库里没有任何二进制资源。
2. **全链路降级**：模块 stub、着色器编译自检、软阴影回退、无 WebAudio 静音、字体加载超时兜底——几乎不会白屏。
3. **单文件交付**：一个 URL 就是完整游戏，`python3 -m http.server` 即可离线运行（字体除外）。

### 2.2 模块装配与降级

```js
async function r(h, f, p, d = false) {   // h=模块名, p=构造函数, d=是否关键
  const v = performance.now();
  try { t[h] = await p(); }
  catch (x) {
    console.error(`[boot] module "${h}" failed: ${x && x.stack || x}`);
    if (d || !dr[h]) throw x;            // 关键模块必须成功
    t[h] = dr[h]();                      // 否则用 stub 顶上
  }
  const g = performance.now() - v;
  if (g > 150) console.log(`[boot] ${h} ${g.toFixed(0)}ms`);   // 慢模块上报
}
```

`render / level` 是 `d=true` 的关键模块；其余全部可降级。这带来一条很实用的性质：**只要渲染器和关卡能起来，游戏永远能进得去**。

### 2.3 stub 工厂（`dr`）实际内容

| stub | 提供什么 | 关键点 |
|---|---|---|
| `ground` | `update`、`wetnessAt()=>0.5`、`isPuddle()=>false` | 关卡会补一块 400×400 沥青地面，地面缺失也不掉坑 |
| `backdrop` | 只有 `update` | 远景消失，玩法不受影响 |
| `fx` | 空函数全套：`muzzleFlash/tracer/impact/sparks/smoke/explosion/debris/shell/decal/dust/splash/addEmitter` | `addEmitter()` 返回带 `stop/setPos` 的哑对象 |
| `audio` | `play/loop/setIntensity/setInterior/setVolume/setPaused` 全空 | `loop()` 返回带 `setPos/setGain/setPitch/stop` 的哑句柄 |
| `weapon` | 30/30 弹匣、`name:"KR-7"`、`spread:.01` | 有 HUD 数据，不会出现 `undefined` |
| `enemies` | `list: []`、`raycast: ()=>null`、`aliveCount: ()=>0` | 无敌人但可通关 |
| `hud` | 全空函数 | 无界面 |
| `mats` | 按名缓存 `MeshStandardMaterial`、`emissive()`、`decal()/label()` 返回透明空材质 | 永远不会 `mats.get()` 返回 undefined |

注意 `weapon` stub 名字是 `KR-7`，而真实武器叫 `PAC-9 Longshore`——这不是 bug，是**降级路径特意用了不同的占位名**。

### 2.4 三层错误捕获

```js
window.__frames = 0; window.__ready = false; window.__fatal = null; window.__errors = [];
window.addEventListener("error", i => { window.__errors.push(String(i.message)); });
{ let i = console.error.bind(console);
  console.error = (...e) => { try { window.__errors.push(e.map(t => t && t.stack || String(t)).join(" ").slice(0, 400)); } catch {} i(...e); }; }
```

- 第 1 层：`window.onerror` 收集未捕获异常。
- 第 2 层：**把 `console.error` 劫持**成环形日志，任何被 catch 后打印的错误也会进 `__errors`（只留前 400 字符防爆）。
- 第 3 层：致命错误走 `bM()`，在页面底部插一个 `#fatal` 条，把堆栈直接显示给用户，而不是白屏。

全局状态机：`__frames`（帧计数）、`__ready`（第 2 帧后置 true）、`__fatal`、`__errors`。这组变量是外部自动化测试/截图工具的唯一抓手。

### 2.5 showcase 模式

`?show=mats|level|backdrop|ground|fx|weapon|enemies|props|render` 会切换成“展台模式”：不建关卡、不建玩家，用一个 80×80 混凝土地面当背景，各模块暴露自己的 `showcase(t)`：

```js
if (n) {  // n = showcase 名称
  t.level = { stub: true, playerStart: {...}, objectives: [], ... };
  t.backdrop = dr.backdrop(); t.ground = dr.ground(); t.physics.build();
  t.audio = dr.audio(); t.hud = dr.hud(); t.player = nP(t);      // 全 stub
  t.weapon = dr.weapon(); t.enemies = dr.enemies();
  t.game = { state: "showcase", update: () => false, start() {} };
  f = await gM[n].showcase(t);
}
```

这是很少见的做法：**每个子系统都自带一个可视化单元测试**，改材质/武器模型时不用跑完整关卡。`gM` 就是模块注册表：

```js
var gM = { mats: qg, level: cv, backdrop: mv, ground: vv, fx: Sv,
           weapon: Xv, enemies: ex, props: $g, render: Vg };
```

## 3. 主循环

### 3.1 帧序

```
input.update
game.update(dt)                   → 返回 d（是否更新世界）
  if d: player → weapon → enemies
wetness 插值（相机是否在棚屋内）
if state !== "paused": fx → ground → level → backdrop → mats
audio → hud
render.frame(dt)                  ← 世界 + 视模型 + 后处理
input.endFrame
__frames++
```

关键性质：**暂停时仍然跑 `audio / hud / render`**，所以菜单背后画面与声音继续存在，只是世界冻结。这个细节对“暂停”到底该停什么做了明确取舍。

### 3.2 时间

```js
let f = (h - l) / 1000; l = h;                      // 真实 dt
a = a ? a * 0.95 + f * 0.05 : f;                    // 平滑 fps
let p = Math.min(f, .05);                            // dt 上限 50ms
i.dt && (p = +i.dt);                                 // ?dt= 固定步长
```

`dt` 锁 0.05 s 是防“切标签回来物理爆炸”的标准做法；`?dt=` 是给录制和基准测试用的确定性入口。

### 3.3 错误隔离

```js
let u = (h, f) => {
  let p = t[h];
  if (p && p.update) try { p.update(f); }
  catch (d) { u.err[h] || (u.err[h] = 1, console.error(`[loop] ${h}.update threw: ${d && d.stack || d}`)); }
};
u.err = {};
```

每个子系统独立 try/catch，**同一模块只打印一次**，避免一帧 60 次刷屏。`render.frame` 也是单独 try/catch。

### 3.4 武器湿滑度

```js
let v = t.level.interiorBoxes[0], g = t.camera.position;
let x = g.x > v.min.x && g.x < v.max.x && g.z > v.min.z && g.z < v.max.z && g.y < v.max.y;
c += ((x ? .3 : 1) - c) * Math.min(1, p * (x ? .25 : .6));
t.weapon.setWetness(c);
```

进棚 0.3、出棚 1.0，用不同的时间常数插值（进棚更快），驱动武器材质的粗糙度与法线强度。

### 3.5 `#bench`

`eP(t)` 建一个 `pre`，把相机-disable，沿 `level.cinematicPath`（或默认两点）做 smoothstep 往返漫游，每 1 秒输出：

```
frame ms avg / median / p99  => fps
buffer WxH  quality  dpr
stats {calls, tris, ...}
errors N + 前 6 条
```

这是**只靠 URL 就能做性能回归**的设计，不需要任何外部工具。

## 4. 渲染系统（`Hg`，L4733）

### 4.1 全局常量层（L4180 起）

```js
var oi = { min:new W(-40,0,-30), max:new W(40,30,30), groundY:0, seaY:-1.6, quayX:30 },
    Mn = { dir:new W(.916,.225,.331).normalize(), color:new Ve(1,.72,.42), intensity:9 },
    en = { zenith:new Ve(.055,.085,.13), horizon:new Ve(.95,.55,.28),
           horizonAway:new Ve(.16,.22,.3), fog:new Ve(.42,.47,.52) },
    Pi = { eye:1.68, crouchEye:1.05, radius:.32, height:1.8, fov:74, viewFov:54 };
```

- 世界 80×80 m，Y 上限 30，海面在 −1.6，码头岸线在 `x = 30`——**“地面/海面”用 x 坐标一刀切**，这是整份代码里最省的物理决策。
- 太阳方向固定为低角度暖光（黄昏），强度 9。
- 大气三层色：天顶、朝向太阳的地平线（橙 0.95/0.55/0.28）、背离太阳的地平线（冷 0.16/0.22/0.3）。

### 4.2 渲染器配置

```js
new WebGLRenderer({ antialias:!1, powerPreference:"high-performance", alpha:!1, depth:!0, stencil:!1 })
renderer.autoClear = false;            // 手动控制清屏
renderer.shadowMap.autoUpdate = false; // 阴影按需更新
renderer.info.autoReset = false;       // 统计跨帧累加
```

关掉 MSAA 是因为自己实现 FXAA；`autoClear=false` 是因为世界与视模型要分两次渲染。

### 4.3 双相机与视模型

| 相机 | FOV | near/far | Layer |
|---|---|---|---|
| 世界相机 | 74（ADS 52） | 0.08 / 900 | 0 |
| 视模型相机 | 54 | 0.01 / 10 | 1 |

```js
n.render(r, a);            // 世界
n.clearDepth();            // 清深度
s.depthRange(0, .05);      // 压缩深度范围
n.render(r, l);            // 视模型
```

顺序 + `clearDepth` + `depthRange` 三段组合是标准的 viewmodel 做法：武器永远不被墙插穿，且能独立用窄 FOV 让枪显得更“稳”。

### 4.4 阴影：自定义 PCSS

阴影贴图按需更新：

```js
(i.quality.name === "ultra" || e.shot || (T & 1) === 0 || !h.shadow.map) && (n.shadowMap.needsUpdate = !0);
```

即 ultra/截图模式每帧更新，其余**隔帧**更新。

采样部分直接接管了 three 的 `shadowmap_pars_fragment` chunk（自检失败会还原）：

```glsl
for ( int i = 0; i < ${t}; i ++ ) {
  vec2 o = slVogel( i, ${t}, phi ) * searchR;          // 螺旋盘采样找 blocker
  float d = unpackRGBAToDepth( texture2D( shadowMap, sc.xy + o ) );
  float z = zr + dot( o, dz );
  if ( d < z ) { blk += d; nb += 1.0; }
}
if ( nb < 0.5 ) return 1.0;
// --- penumbra: grows with blocker distance (sun half-angle scaled up for look) ---
float distM = max( zr - avg, 0.0 ) * SL_DEPTH;
float penM  = clamp( distM * 0.022 * shadowRadius, 0.012 * shadowRadius, 0.60 * shadowRadius );
vec2 filtR  = max( vec2( penM ) / SL_FRUSTUM, texel * 1.25 );
...
// fade to lit at the very edge of the map so the frustum border never shows
lit = mix( 1.0, lit, smoothstep( 0.0, 0.02, min( e.x, e.y ) ) );
```

要点：
- `SL_FRUSTUM` / `SL_DEPTH` 是 CPU 侧按相机视锥拟合写入的 uniform（拟合而不是固定正交框，能提高分辨率利用率）。
- 半影随 blocker 距离线性增长，并夹在 `[0.012, 0.60] × shadowRadius`，防止近期过锐、远处糊成一片。
- 贴图边缘淡出到“受光”，这是避免视锥边界出现一条硬线的关键 hack。
- 失败回退：chunk 编译不通过 → 还原原 chunk 并把 `shadow.radius` 设为 2。

### 4.5 后处理管线

`Hu`/`A` 这一层自己管理全部 RenderTarget 与 pass，不依赖 EffectComposer。阶段顺序（README 之外的实测顺序）：

| # | 阶段 | 关键实现 |
|---|---|---|
| 0 | pre-pass 列表 | `addPrePass(fn)`：地面模块在此挂平面反射（`render.renderWorld(cam, rt)` 临时切层/关层） |
| 1 | HDR 场景 | 世界 + 视模型渲到半浮点 RT |
| 2 | 深度拷贝 | `gl_FragDepth = texture2D(tDepth)` 的全屏 quad 把深度“写”进颜色 RT |
| 3 | 半分辨率深度 | `texelFetch` 精确取 2× 像素，线性化到视空间 z |
| 4 | AO | 半分辨率螺旋采样（`AO_TAPS`），**按亮度淡出**，joint bilateral 上采样 |
| 5 | 体积光 | 半分辨率 raymarch，双 lobe HG 相位，棚内粉尘盒加成，远端解析式雾接续 |
| 6 | Bloom | 多级降采样（首级**部分 Karis 平均**压 firefly）→ tent 上采样回混 → 横向 streak（±7 tap 高斯，阈值随当前曝光缩放） |
| 7 | 运动模糊 | 上一帧 viewProj + 深度重投影 |
| 8 | 自动曝光 | 5×7 中心加权 log 平均 + 12 采样太阳可见度，ping-pong 两 RT 时间适应，带 NaN 守护 |
| 9 | 合成 | 曝光 → ACES(Hill) 拉向 AgX（`uAgxMix`）→ 分级 → 眩光/鬼影/镜头脏污（70 个程序化圆斑）→ 暗角/受伤/ADS → FXAA → 颗粒 → dither |
| 10 | 输出 | `setRenderTarget(null)`，`outputColorSpace` 线性，色调映射自己算 |

着色器里的注释直接说明了设计意图，这些是全文质量最高的部分：

```
// exact texel fetch: sampling at a texel corner would pick rows unpredictably and band the AO on grazing floors
// two-lobe phase: tight forward lobe for the gold glow toward the sun + a broad lobe so side-lit shafts stay visible
// dusty interior (the shed): thicker air so sun shafts through doors, louvres and roof holes read; less sky ambient
// art direction: beams near the eye read strongly (shafts between stacks), the far field stays a restrained veil
// analytic continuation for far geometry (ship, cranes, skyline): fades into the horizon colour of that direction
// joint bilateral upsample of the half-res buffers
// occlusion belongs to ambient light: fade it out on brightly lit pixels so sunlit surfaces never get dirty halos
// partial Karis average on the first downsample: tames fireflies without killing the sun
// ---- AgX (Filament/Blender fit, as in three.js) ----
// "punchy"-style look: a little more contrast and chroma than the base AgX rendering
// veiling glare + a few soft diffraction spikes / ghosts along the sun -> centre axis / halo ring opposite the sun
// radial chromatic aberration (tiny; grows a little when hurt)
// filmic curve: ACES (Hill fit) for punch and burning oranges, pulled toward AgX so highlights roll off to white
// split tone: teal shadows, warm highlights
// lifted, slightly teal blacks
// vignette: base + low health + ADS tightening
// light unsharp mask, backed off on strong edges (those belong to FXAA)
// animated, luminance-weighted film grain
// dither against banding in the sky gradients
```

注意第 9 步：**不是纯 AgX，也不是纯 ACES**，而是 ACES(Hill) 的结果按比例拉向 AgX，用来同时获得“橙色烧得亮”和“高光滚到白”两个特性。这类混合在商业项目里也常见，但很少见到有人写清楚原因。

### 4.6 曝光

```glsl
uniform sampler2D tAdapt; uniform float uExposure, uKey, uMinE, uMaxE, uAuto;
float slExposure(){
  float a = texture2D(tAdapt, vec2(0.5)).r;
  return uExposure * mix(1.0, clamp(pow(uKey / max(a,1e-4), 0.85), uMinE, uMaxE), uAuto);
}
```

`pow(..., 0.85)` 是“眼睛适应别太激进”的手感修正；`uAuto=0` 时退化为纯手动曝光（截图模式用）。

测光是 5×7 的**中心加权对数平均**，再加上“太阳是否被可见”作为额外项：

```glsl
for (int y = 0; y < 5; y++) for (int x = 0; x < 7; x++) {
  vec2 uv = (vec2(float(x), float(y)) + 0.5) / vec2(7.0, 5.0);
  float w = 1.0 - 0.75 * smoothstep(0.1, 0.55, length(uv - 0.5));   // centre-weighted metering
  ls += log(max(luma(texture2D(tLum, uv).rgb), 1e-4)) * w;  ws += w;
}
float avg = clamp(exp(ls / ws), 0.002, 40.0);
for (int i = 0; i < 12; i++) { ... step(0.99999, texture2D(tDepth, uv).r) ... }   // 太阳可见度
vec4 prev = texture2D(tPrev, vec2(0.5));
float a = mix(prev.r, avg, uRate);
if (!(a > 0.0) || a > 1e4) a = avg;                                  // NaN / first-frame guard
```

两个细节值得记：
- **太阳可见度参与适应**：转头看见太阳时曝光回落得更快，避免“一转身画面全白”。
- **NaN 守护**：`!(a > 0.0)` 同时挡掉 NaN 与 0，切标签、改分辨率、首次运行时不会把曝光锁死。

### 4.8 自适应分辨率与自动降档

```js
// X = 当前 scale（0.6..1），F = 近若干帧平均帧时间（ms）
F < 17.4 && X < 1  && S.upWait <= 0 → X += .1, upWait = 2      // 有余量就升

X <= .6 && F > 26 → 连续 2 次触底后：ultra→high→medium→low 直接降档
```

也就是说：**先降分辨率到 0.6，还救不回来才降档位**，并且降档后把 `scale` 重置成 0.8 重新爬。这套“两段式”策略比单纯降分辨率体验好得多（纹理与体积光步数才是真瓶颈时，降分辨率没用）。

外部 ×1.35、室内 ×(Ky/Jy)——"室内更暗"不是调色，而是有真实环境光差。`compileAsync(scene, camera)` 也会对室内环境再编译一次，避免第一次进棚掉帧。

## 5. 程序化材质（`Gg`，L5442）

### 5.1 架构

```
GLSL surf(uv)  ──MRT──▶  o0 albedo(sqrt) + alpha
                         o1 AO / roughness / metallic
                         o2 height（整数 + 小数）
        │
        ├─ copy pass  → albedo 纹理（sRGB）
        ├─ copy pass  → ORM 纹理（swizzle）
        └─ normal pass（height 求导）→ 法线纹理
```

关键代码：

```js
void emit(vec3 c, float a, float h, float ao, float r, float m) {
  o0 = vec4(sqrt(clamp(c, 0.0, 1.0)), sat(a));          // 存 sqrt 用精度换暗部细节
  o1 = vec4(sat(ao), clamp(r, 0.03, 1.0), sat(m), 1.0);
  float hh = sat(h) * 255.0; float fl = floor(hh);
  o2 = vec4(fl / 255.0, hh - fl, 0.0, 1.0);             // 整数/小数分通道压 8bit 高度
}
```

烘焙实现要点：

```js
let G = new si(D, D, { count:3, depthBuffer:!1, generateMipmaps:!1, ... });  // MRT
let j = g(e3 + Tn[U.fn] + t3, { uP, uSeed, uTexel });                        // 按材质名缓存 shader
y(G, j);                                                                     // 渲到 MRT
Q.copy.uniforms.tA.value = G.textures[0]; y(ne, Q.copy);                     // albedo → sRGB
Q.copy.uniforms.tA.value = G.textures[1]; y(re, Q.copy);                     // ORM
y($, Q.normal);                                                              // height → normal
for (let ue of [ne, re, $]) ue.texture.repeat.set(1 / C[0], 1 / C[1]);       // 平铺一次 = 多少米
```

尺寸策略：

```js
let q = Math.round(s * O.size);                    // s = min(quality.tex, 1024)
if (O.hero && n >= 2048) q = 2048;                 // hero 材质可到 2048
q = Math.max(32, q);
```

- 同一分辨率复用同一个 MRT 目标（`h: Map<尺寸, RT>`），所以 27 套材质只占用少数几张 3 通道 RT。
- 纹理按材质名缓存，`repeat` 设为 `1/平铺米数`，材质函数内部就永远按 0–1 UV 写。
- 各向异性过滤取 `min(8, getMaxAnisotropy())`。

### 5.2 共享的“损伤模型”

材质之间的真实感来自**共享函数**而非各自乱写：

```glsl
// scattered straight scratches
float scr(vec2 uv, float f, float s, float w, float ang, float spread, float dens){ ... 3×3 cell ... }

// chip: 0 = intact paint .. 1 = through to substrate; stain: thin oxide halo; run: rust run below damage (-V is down)
void paintDmg(vec2 uv, float amt, out float chip, out float stain, out float run){
  float zone = smoothstep(0.58, 0.82, fbm(uv, vec2(2.0), 3, 22.0));   // 损伤成簇，面板大部分干净
  float c1 = chipsF(uv, vec2(20.0,11.0), 23.0, dn, 0.24);            // 竖向拉长的剥落
  float c2 = chipsF(uv, vec2(64.0,40.0), 24.0, dn*1.6, 0.34);
  float c3 = smoothstep(th, th+0.03, wearN + ...);                    // 整体磨损
  float s1 = scr(uv, 5.0, 26.0, 0.0035, 0.0, 0.4, ...);              // 两道方向的划痕
  float rr = 0.0;
  for (int i=1; i<=4; i++){                                           // 4 次迭代的锈水流挂
    vec2 q = uv + vec2(0.0, float(i)*0.034);
    rr = max(rr, src * (1.0 - float(i)/5.0));
  }
  run = rr * smoothstep(0.5, 0.78, streak);
}
```

共用同一个 `paintDmg` 的结果是：红、蓝、绿、白、灰所有油漆箱的掉漆**看起来是同一种物理过程**，这是“美术一致性”的代码实现方式。

### 5.4 材质接管 three 的 chunk

```js
bA = It.aomap_fragment.replace("texture2D( aoMap, vAoMapUv ).r", "slORM.r");
// 以及在 common / map_fragment / roughnessmap_fragment / metalnessmap_fragment /
// normal_fragment_maps / aomap_fragment 里注入 slUv、slWetK
```

`slORM` 让 AO/粗糙度/金属度从**一张** ORM 纹理里取（省一次采样），`slWetK` 让“下雨”成为全局 uniform 而不是逐材质开关，`slUp` 保证只有朝上的表面变湿。实测全文 `dispose` 出现 172 次，说明这套自建资源管线的释放也是成套写的。

## 6. 天空与大气

### 6.1 结构

天空是一个全屏 `ShaderMaterial`（`// SALTLINE_SKY` 标记），前置两段公共 GLSL：

```glsl

float n2(vec2 p){ vec2 i=floor(p), f=fract(p); f=f*f*(3.0-2.0*f); return texture2D(tNoise,(i+f+0.5)/256.0).r; }

  c = mix(c, uHor*vec3(1.9,1.55,1.2), pow(ts,6.0));

```


### 6.2 云层分解

```glsl
vec2 cuv = d.xz / (h + 0.10) * vec2(0.62, 0.95);   // 云带大致东西向
vec2 q   = cuv + wind;                             // 风
float warp = fbm3(q*0.45 + 7.1);                   // 域扭曲
float dens = fbm5(q + (warp-0.5)*1.3);
float ridg = 1.0 - abs(2.0*fbm3(qq*3.1+5.0) - 1.0); // 脊状云底，随距离淡出防走样
float body = dens*0.74 + big*0.36;
float cov  = smoothstep(0.31, 0.50, body);          // 覆盖率
float edge = mix(0.030, 0.285, pow(ts,1.7));        // 云层在太阳方向的缺口
float deck = smoothstep(edge-0.035, edge+0.11, h + rag*(0.35+ts));
float hole = smoothstep(0.972, 0.9985, mu + (dens-0.5)*0.012);  // 太阳永远烧穿一个破洞
cov *= 1.0 - 0.93*hole;
```

设计约束直接写在注释里：`// the sun always burns through a ragged hole in the gap, never sits behind solid cloud`——**太阳绝不被实心云挡住**，这是为了保证体积光、眩光、反射、曝光全链路有一个稳定的主光源。

## 9. 关卡、物理、导航（L5442）

### 9.1 静态合批

关卡建完后按 `(材质, castShadow, receiveShadow, layers)` 分组，把静态网格 `geometry.clone().applyMatrix4(matrixWorld)` 后合成**一个** Mesh：

```js
let o = new wt;
for (let r of n.values()) { let a = new Qe(Ii(r.geos), r.mat); a.castShadow = ...; o.add(a); }
```

无法合并的（`noMerge`，例如需要独立动画/剔除的大件）被 attach 到动态根，并保留世界矩阵的 `matrix/decompose` 结果。实测 drawcall 能被压到两位数，这是这项技术存在意义的直接证据。

### 9.2 物理数据结构

```js
addBox(min, max, opts) → {
  min, max,
  surface: opts.surface || "concrete",   // 命中音效/特效分类
  tag: opts.tag || "",                    // 逻辑标签（relay / door / crate）
```

### 9.3 射线

```js

  let w = maxDist, S = null;
  // 1) 地面平面 groundY=0（仅当 dir.y < 0 且落点在岸线之内）
  if (C < -1e-6) { let F = (oi.groundY - U) / C; if (F > 0 && F < w) { if (q + D*F <= oi.quayX) { w = F; O = 1; } 
                   else { let ne = (oi.seaY - U) / C; ... } } }
  // 2) AABB slab 法逐个求交
}
```

地面与海面用解析式、集装箱用 slab 法，省略了“为一块平地建三角网格”的开销。

### 9.4 导航网格 + A*

```js
Ls = .5;  // 0.5 m 一格
Ya = -40; EA = 31; ol = -32; SA = 30;
qt = round((31 - (-40)) / .5) = 142;      // X 方向 142 格
Qs = round((30 - (-32)) / .5) = 124;      // Z 方向 124 格
```

约 17.6 k 个 `Uint8Array` 单元，建关卡时把每个碰撞盒按 `noNav / bulletOnly / 高度不符` 过滤后反向标记 blocked，同时把岸线外与边界的 1 格全部封锁。

A* 的实现细节值得单独记一笔：

```js
// 八邻域 + 禁止切角
if (n[j] || v[j] === g || (D && T && (n[U*qt+C] || n[G*qt+q]))) continue;

// 二叉堆（inline，两个平行数组 x/y）
function b(_,M){ ... 上浮 ... }  function m(){ ... 下沉 ... }

// 启发式：八方向对角距离
S = O => { let q=|O%qt-E|, U=|⌊O/qt⌋-w|; return q+U+(1.4142-2)*Math.min(q,U); };

// 搜索节点上限 9000，超了返回 null（避免卡帧）
if (++z > 9e3) return null;
```

另外两个查询：

- `u(x,z)`：取最近可行走格，失败时按**环形扩张**（半径 1..12）找最近空格——用于出生点与目标点纠偏。
- `h(a,b)`：Bresenham 式转向线检查（含对角穿墙判断），供 AI 的 LOS 与“能否直线追击”判断。

**局限**：这是纯 2D 网格，没有层高概念，所以 AI 不会上集装箱顶或棚顶，也不会从高处跳下寻路。

## 12. 音频（`c_`，L5928）

### 12.1 总线图

```

near   (0.95) ├→ lowpass(20k, Q.5) → S ─┐
amb    (0.55) ┘                          │
dry    (1.00) ────────────────────────→ A ┴→ compressor → M(0.45) → waveshaper → w(0.9) → destination

```

压缩器参数：`threshold −10 dB / knee 6 / ratio 6 / attack 0.002 / release 0.14`。
waveshaper 是**软削波**（0.6 以下线性，以上用 `tanh` 收，`oversample:"2x"`），这是把“枪声多、层次糊”问题压住的实用做法：


两条 `ConvolverNode` 分别对应室外与棚内，用 `setInterior` 插值过渡。

### 12.2 cue 表结构


| 字段 | 含义 |
|---|---|
| `gen` | PCM 生成函数 |

### 12.3 合成与烘焙

```js
// 每帧最多花 6ms 做合成，然后 setTimeout(12) 让出主线程

...
```

- 启动时先烘 `boot:1` 的 cue，其余进队列分帧烘。
- 烘好的 `AudioBuffer` 按 `name#variant` 缓存，重复请求走缓存。
- 播放前若未烘好，注册回调排队（`b()`），烘完立刻补播。

### 12.4 空间化细节

不是简单的 `PannerNode` 全量使用，而是**按距离分三类**：

- 近处关键音（枪、脚步）：`bus:"near"`，几乎不做距离衰减。
- 世界音（命中、敌人引擎）：HRTF 空间化 + `ref/roll` 距离模型。
- 环境音（雾笛、吊索、集装箱碰撞）：低优先级、`jitter` 随机、`gain` 极低。

敌人引擎声的 pitch 随移动速度变化：

```js
pe.h.setPitch(pe.tune * (.88 + .3 * clamp(speed / 3, 0, 1)));   // hound
pe.h.setPitch(pe.tune * (.94 + .3 * clamp(speed / 10, 0, 1)));  // gull
```

`tune` 每个实例 ±5% 随机，避免 8 只狗同频蜂鸣。

### 12.5 音乐

5 条分层循环：`music_drone / music_ost / music_perc / music_brass / music_motif`，随 `intensity` 叠加：

```js
c.intensity = allCut || queue || waveHot ? 1 : alertT > 0 || alive ? .6 : .15;
```

`intensity` 由游戏模块每帧算，音频模块只负责响应——玩法与音频之间没有互相调用。

### 12.6 事件订阅表（节选）

| 事件 | 音频行为 |

| `weapon:fire` | `rifle_shot` 轮换 4 个变体、jitter 0.012 |
| `weapon:reload` | 按 `phase` 分派 `magout/magin/bolt/start` |
| `shell:bounce` | 3 变体、`roll:.7` |

| `thunder` | `thunder`，同时驱动后处理闪光 |

### 12.7 一个细节：步枪尾音

```js
function fo(t) {
  tailK < .95 && ze("rifle_tail_out", { gain: t*(1-tailK) });
  tailK > .05 && ze("rifle_tail_in",  { gain: t*tailK });
}
// 开火时才切换，且 lastShot 间隔 > 0.28 s 才切一次，防止连发时刷爆
```

用“淡出旧循环 + 淡入新循环”代替“开一个停一个”，连发时不会有可听见的接缝。

## 13. UI / HUD / 菜单

### 13.1 结构

HTML 只有 3 个节点；`#ui` 之内全部由 JS 创建：

| 模块 | 产出 |
|---|---|
| HUD（L6076） | 罗盘带（8 方位 `N/NE/E/...`）、目标追踪、继电器计数、波次警告、准星 + 命中标记、方向受伤弧、交互提示、击杀信息流、生命分段条、弹药、武器名、世界标记 |
| 菜单（L6099） | 标题卡、暂停、阵亡、结算（Debrief）、设置/操作面板、位置卡（location card） |
| 触屏（L5928） | 虚拟摇杆 + 射击/瞄准/装填/跳跃/使用/暂停按钮 |

菜单模板是**可读的 HTML 字符串**，直接带语义属性：

```html
<section class="m-screen m-card m-debrief" data-s="complete" aria-label="Debrief">
  <div class="m-rating"><span>Rating</span><b data-f="rating">Clean</b></div>
  <dl class="m-stats">
    <div><dt>Time</dt><dd data-f="time">00:00</dd></div>
    <div><dt>Accuracy</dt><dd data-f="acc">0%</dd></div>
    ...
```

### 13.2 更新策略（性能关键）

HUD 每帧都在跑，但**几乎所有 DOM 写入前都和缓存值比较**：

```js
if (Xe !== X.hp) { X.hp = Xe; z.textContent = String(Xe); ... }        // 生命
Oe !== we.rot && (we.rot = Oe, we.el.style.transform = `... rotate(${Oe}deg)`);  // 受伤弧用 transform 旋转，不重排
pt !== we.op && (we.op = pt, we.el.style.opacity = String(pt));        // 透明度按 0.05 量化
```

其他手法：
- 字幕 / 目标文本用打字机（`58~46 字/秒`），只在字符数变化时写 `textContent`。
- 击杀信息流 4 s 生命周期，`.out` class 触发淡出后 `remove()`。
- 罗盘用 `translate3d` 位移，不重排。

### 13.3 面板与焦点管理

```js
s.addEventListener("keydown", e => {
  if (e.code === "Escape" && !panel.hidden) { close(); e.stopPropagation(); e.preventDefault(); }
  if (e.code === "Tab" && !panel.hidden) { /* 手动首尾循环，把焦点困在面板内 */ }
});
```

`role="dialog" aria-modal="true"` + 焦点陷阱 + 打开时 `focus({preventScroll:true})` + 关闭时归还焦点——这套是标准无障碍做法，在游戏里不常见。

### 13.4 设置持久化

```js
var fM = "saltline.settings.v1", XC = { quality:"auto", sens:1, invertY:false, volume:.8, fov:74 };
// 读取时逐字段校验
(i.quality === "auto" || dM.includes(e.quality)) && (i.quality = e.quality);
Number.isFinite(e.sens) && (i.sens = Math.min(3, Math.max(.2, e.sens)));
```

只有 5 个字段，但每个都做了范围校验（`sens 0.2–3`、`quality` 白名单、`fov` 归一到 `Pi.fov` 附近），坏数据不会把游戏搞挂。

### 13.5 触屏与安全区

CSS 用 `env(safe-area-inset-*)` 生成 `--sat/--sab/--sal/--sar` 与 `--gl/--gr`，HUD 与菜单全部按这些变量定位，刘海屏/圆角屏不会压字。触屏按钮 `pointer-events:auto` 单独恢复，其余 HUD 层 `pointer-events:none`。

### 13.6 无障碍清单

- `aria-label` × 15（区域、菜单、按钮）
- `role="status"` / `aria-live="polite"`（字幕）
- `aria-pressed`（开关类按钮）、`aria-selected`（tab）
- Tab 焦点陷阱 + Esc 关闭
- `prefers-reduced-motion: reduce` 下把动画时长压到 `0.01ms` 并关掉警告闪烁

## 14. 性能工程

### 14.1 预算手段清单

| 手段 | 位置 | 收益 |
|---|---|---|
| 静态合批（按材质分组） | 关卡 | drawcall 数千 → 两位数 |
| 标签/贴花图集 | 关卡 + `mats` | 带字几何也能进合批 |
| 阴影隔帧更新 | `render.frame` | 阴影 pass 减半 |
| 半分辨率 AO / 体积光 | 后处理 | 两个最贵的 pass 面积 ÷4 |
| 平面反射半分辨率 + 档位可关 | `ground` | 省一整遍场景 |
| 自适应分辨率（0.6–1.0） | `render` | 稳定 60 fps 的主要手段 |
| 两段式自动降档 | `render` | 纹理/步数瓶颈才降档 |
| 对象池（敌人/弹道/粒子/贴花） | 各模块 | 零运行时分配 |
| HUD 脏值比较 | `hud` | DOM 写入从每帧若干次降到事件级 |
| 视模型单独相机 + Layer | `render` | 枪不参与世界裁剪，省一遍 |
| 渲染器 `autoReset:false` 跨帧统计 | `render` | 统计本身不额外开销 |

### 14.2 启动成本

首屏是**纯计算**：27 套材质烘焙（含 3 次全屏 copy + 1 次求导）、标牌图集、地面高度场、音频 PCM、着色器编译。低端机首次进入偏慢，这是“零资源、全程序化”的必然代价。作者的缓解手段是：

1. 分阶段进度条（`Nr` + `await KC()`）；
2. 音频分帧合成（6 ms/帧）；
3. `compileAsync` 预热（含室内环境再编译一次）；
4. 慢模块 > 150 ms 打日志，便于定位。

### 14.3 已知瓶颈（按影响排序）

1. **体积光 raymarch**：半分辨率下 ultra 40 步，仍是最大头。
2. **PCSS 采样**：blocker search + filter 两轮 Vogel 采样，4096 阴影贴图时带宽压力大。
3. **平面反射**：再来一遍场景渲染，high/ultra 才有。
4. **材质烘焙/编译**：只在启动时，但会影响首屏。
5. **DOM HUD**：做了脏值比较后已不是瓶颈，但每帧 `Math.round` 与字符串拼接仍有小开销。

## 15. 工程质量评价

### 15.1 做得好

1. **降级设计是系统性的，不是补丁**：从模块 stub、着色器 chunk 回退、软阴影回退、无 WebAudio 静音，到字体加载超时，几乎每层都有 Plan B。
2. **性能预算写在代码里**：合批、图集、隔帧阴影、半分辨率、自适应分辨率、两段式降档——每一条都能对应到具体代码行与常量。
3. **玩法层与渲染层解耦**：玩法只写 `render.post = {damage, lowHealth, ads, flash, fade, saturation, shake, wet}` 与事件，从不碰着色器；音频只订阅事件，从不被玩法调用。
4. **可观测性**：`__stats / __frames / __errors / #bench / ?show= / ?dt= / ?seed=`，一套完整的无依赖调试面。
5. **着色器注释写的是“为什么”**：`occlusion belongs to ambient light`、`the sun always burns through a ragged hole`、`exact texel fetch: ... would band the AO on grazing floors`——这些是排错经验，不是复述代码。
6. **一致性的复用**：`paintDmg` 一处定义、五种油漆共用；`wetnessAt` 一处高度场、三处消费；`sm` 顶点色噪声统一 ±10%。

### 15.2 局限

1. **不可维护**：238 KB 单行、2–3 字符标识符、无模块边界、无源码。任何改动靠全局搜索，PR review 无意义。
2. **物理过于简化**：只有 AABB + 两个水平面，没有凸体、斜坡滑动、角色间碰撞；站在箱子边缘的判定会很“方”。
3. **导航是 2D 网格**：AI 不跨层，上不了棚顶，也不会为了绕路而下到低处——关卡因此被限制在同一平面内。
4. **首屏全计算**：无预烘资源，冷启动依赖 CPU/GPU 性能；移动端 low 档也要几百毫秒到数秒。
5. **无 i18n 层**：文本硬编码在模板字符串里，中文版是整文件复制改名（`saltline中文版.html`），这本身就是维护成本的证明。
6. **无测试、无构建、无源码**：仓库只有一个产物，无法复现构建，也没有单元测试；唯一“测试”是 `?show=` 展台。
7. **数值散落**：大量魔法数字直接写在表达式里（虽然关键数值确实收敛到了 `Mt / Zv / Kv / Yi / Pr` 等表里）。

### 15.3 分维度评分（主观，仅供参照）

| 维度 | 分数 | 理由 |
|---|---|---|
| 渲染实现质量 | A | 自建后处理 + PCSS + 双段曝光 + AgX/ACES 混合，均有注释说明取舍 |
| 资源程序化程度 | A+ | 零二进制资源，材质/模型/音效/天空全代码生成 |
| 健壮性 / 降级 | A | 六层降级，实测几乎无白屏路径 |
| 性能工程 | A− | 手段齐全，但体积光与 PCSS 的预算仍偏激进 |
| 可维护性 | D | 单行 238 KB + 全压缩标识符 + 无源码 |
| 可扩展性 | C− | 加武器/加关卡需要读懂 690 KB 压平代码 |
| 无障碍 / 设置 | B+ | 焦点陷阱、aria、reduced-motion 都有，但只有 5 个设置项 |
| 玩法深度 | B | 一个关卡、两种敌人、三个目标，是“技术 demo”而非完整产品 |

**一句话结论**：这是一份**为“交付一次惊艳体验”而极致优化、为“后续维护”完全放弃**的代码；在 demo/技术展示维度接近满分，在产品工程维度不合格。

## 16. 二次开发指南

### 16.1 想改什么，从哪下手

| 目标 | 入口 | 备注 |
|---|---|---|
| 改画质/关体积光 | `Pr`（L4180 附近）+ `Fb`/`Ob` 的 `volSteps` | 直接调档位表最省事 |
| 改手感 | `Mt`（玩家参数表） | 全部集中，改完立即生效 |
| 改武器伤害/射速 | `H_ / O_ / Gv / B_`（L5442 后段） | 与 `zv.playerShot` 联动 |
| 加一把武器 | 复制 `mi` 元数据 + 视模型构建 + `dm` 状态机 | 工作量大，需读懂弹簧轨迹格式 |
| 改敌人强度 | `Zv`（Gull）/ `Kv`（Hound）/ `Ui`（感知与令牌） | 表驱动，最友好 |
| 改关卡 | `C1`：`PROP_SIZES` + 摆放 + `addBox` | 记得同步导航网格与 `interiorBoxes` |
| 加语言 | 替换 `_l`、菜单 HTML 字符串、`hud` 文案 | 中文字体要额外处理（见下） |
| 加音效 | 在 `Go` cue 表加一条 + 写 `gen` 函数 + 订阅事件 | `n/bus/pri/ref/roll` 按需填 |

### 16.2 已知的坑

1. **中文必须关掉“军用模板断笔”**：`label()` 会在字符宽度 50% 处擦一条竖缝（`bridges`），拉丁字母是风格，汉字会被竖线切断。中文版的做法是加 `font` 分支关闭该效果。
2. **单行文件会让编辑器卡死**：修改前建议先按 `;` 或模块边界格式化到临时文件，改完再压回。
3. **着色器编译失败是静默的**：大部分 shader 有 `try/catch` 回退，出错时只会 `console.error` 并降级，画面“看起来还行但少了效果”。排错要看 `window.__errors`。
4. **`localStorage` 版本键是 `saltline.settings.v1`**：加字段不如升版本号，旧数据会被逐字段校验丢弃。
5. **窗口尺寸变化**要经过 `resize()`，它会重建 RT 与自适应 `scale`；直接改 canvas 尺寸会得到模糊画面。
6. **`?dt=` 固定步长下音频仍在跑真实时间**，录视频时要注意音画对齐。

### 16.3 三个“低风险高收益”的小改造

- **加难度选项**：在 `Yi` 与 `Ui` 上做乘数（`spawnStagger`、`maxTokens`、`exposureUp`），不需要碰任何渲染代码。
- **加训练场**：直接复用 `?show=` 展台模式，把 `props/showcase` 扩展成一个可走动的靶场。
- **加截图自动化**：`?shot=1&cam=...&fov=...&exposure=...` 已经齐了，配一个无头浏览器就能批量出图。

## 18. 结语

Saltline 的价值不在“1.4 MB 做出一个游戏”，而在于它展示了**在没有任何美术资源、没有任何外部工具链的条件下，一个系统能做到多完整**：从 PCSS 半影公式到安全区 CSS 变量，从令牌仲裁到焦点陷阱，每一层都有人认真做过取舍，并且把取舍写在了注释里。

同时它也展示了这种做法的边界：**当代码只为“跑起来”服务时，它就很难再被第二个人改动**。这既是 AI 一次性生成 8 小时的产物特征，也是所有“压平交付”方案的共同代价。
